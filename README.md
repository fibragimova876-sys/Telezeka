# Telezeka — семейный мессенджер

Версия 0.2.0 — исходный код MVP для **Windows и Android**, не веб-сайт. Интерфейс на русском. Не содержит готовых EXE/APK: Flutter/Android SDK/Windows C++ toolchain отсутствуют в среде, где подготовлен архив. Сборка клиента и звонки на реальных устройствах ещё не проверены. Серверные тесты выполнены успешно.

## Что реализовано в коде

- Регистрация по общему секретному коду приглашения, вход по email и паролю; новый аккаунт создаётся самим пользователем.
- Личные чаты по @username, закрытые группы и каналы; добавление участников владельцем. В канале пишет только владелец.
- Изменение имени и установка, изменение или удаление username (пустое поле). Личные чаты сохраняются.
- Текстовые и голосовые сообщения, видеокружки с круглым воспроизведением. Android: съёмка через системную камеру либо выбор видео; Windows: выбор файла MP4. Лимит медиа 16 МБ.
- Личные голосовые/видеозвонки через WebRTC (сигнализация через сервер), принять/отклонить, отключение микрофона. Входящие только при открытом приложении. Для связи за сложным NAT понадобится TURN; сервер TURN и временные учётные данные не включены.
- Адаптивный нативный интерфейс, тёмная тема по системной настройке.

- Новое в 0.2.0: редактирование и удаление сообщений, ответы, реакции, закрепление, поиск по тексту, непрочитанные сообщения, отправка и сохранение файлов. Меню сообщения открывается долгим нажатием или правой кнопкой мыши. Сервер также поддерживает переименование групп и удаление участников владельцем; интерфейс этих двух операций ещё не добавлен. Клиент показывает последние 200 сообщений; поиск выполняется по всей доступной истории.

## 1. Собрать .apk и .exe без установки Flutter на свой компьютер

1. Создать **приватный** репозиторий на GitHub. Загрузить в него содержимое этой папки, включая `.github/workflows/build.yml`. Для загрузки скрытой папки удобнее Git или GitHub Desktop. Не загружать реальные пароли, токены, секрет приглашения, файлы базы данных.
2. На вкладке Actions выбрать `Build Android and Windows` → `Run workflow`. Две задачи выполняют сборку на Ubuntu и Windows соответственно.
3. Если сборка завершилась успешно, скачать из Artifacts архивы `telezeka-android` и `telezeka-windows`.
4. Android: извлечь app-release.apk и установить на телефон, при необходимости разрешив установку из выбранного источника. Это тестовый release APK, сгенерированный стандартным шаблоном Flutter; для распространения и обновлений потребуется постоянный собственный ключ подписи. Windows: извлечь **всю** папку, открыть telezeka.exe; соседние DLL и папка data обязательны. Для единого setup.exe можно затем упаковать Release, например Inno Setup.

CI не был запущен в этой среде. Если сборка завершится ошибкой, смотреть шаг с ошибкой во вкладке Actions; могут потребоваться изменения версий Flutter/пакетов или нативных настроек.

## 2. Локальная сборка (альтернатива)

Установить Flutter, Python 3, Android Studio с SDK; для Windows — Visual Studio с Desktop development with C++. На Windows в папке проекта:

```powershell
flutter doctor
python scripts/prepare.py
cd build_app
flutter pub get
flutter analyze lib/main.dart
flutter build apk --release
flutter build windows --release
```

APK: `build_app/build/app/outputs/flutter-apk/app-release.apk`.
Windows: `build_app/build/windows/x64/runner/Release/` (в некоторых версиях Flutter без x64). Для предварительной проверки используйте `flutter run -d windows` или подключённый Android.

Документация: https://docs.flutter.dev/platform-integration/windows/setup ; https://docs.flutter.dev/deployment/android

## 3. Общий сервер — необходим для общения

На компьютере/VPS под Linux с Python 3.10+:

```bash
cd server
export CHAT_INVITE='replace-with-a-long-random-invite-code'
export CHAT_DB='/path/to/private-directory/chat.db'
export CHAT_HOST='127.0.0.1'
export CHAT_PORT='8080'
python3 server.py
```

Указанная папка базы должна существовать и быть доступна только пользователю сервера. Не открывать порт 8080 в интернет. Поставить перед ним HTTPS reverse proxy с действительным TLS-сертификатом, настроить DNS и ограничение частоты запросов (особенно регистрации, входа, загрузок), ограничить общий объём диска; например Caddy или Nginx. Приложение специально принимает только HTTPS. Для первого закрытого теста можно использовать приватную сеть/VPN и доверенный HTTPS-сертификат. Не отключайте проверку сертификата.

Пример Caddyfile (замените домен на свой, настройте DNS):

```
chat.example.org {
    reverse_proxy 127.0.0.1:8080
}
```

Caddy-пример только для закрытого теста; сам по себе не добавляет rate limiting. Для эксплуатации необходимо настроить отдельные лимиты и мониторинг. Настройте постоянный запуск сервера и резервные копии SQLite (SQLite backup API, а не простое копирование работающей базы), ограничьте права файлов. Все устройства вводят один и тот же адрес `https://chat.example.org`, но каждый участник создаёт свой аккаунт с отдельным паролем. Код приглашения передавать только знакомым; при утечке поменять его на сервере.

В проекте используется обычная клиент-серверная архитектура, не Supabase. Нет зависимости от платного сервиса мессенджера; хостинг и TURN могут стоить денег.

## 4. Проверка и ограничения

```bash
cd server
python -m unittest -v
```

Тест проверяет регистрацию, обмен текстом и медиа, запрет доступа постороннего к переписке и медиа, роли канала, удаление username, сигнализацию звонков и отзыв токена при выходе. Клиент ещё нужно собрать, протестировать на двух устройствах, проверить разрешения микрофона/камеры, прямой звонок и связь через TURN. Пароли хранятся на сервере как scrypt-хеши с уникальными солями; токены сессий хешируются, клиент хранит токен только в памяти до закрытия приложения. Медиа загружается на сервер и временно сохраняется локально при воспроизведении. Сквозного шифрования сообщений нет; администратор сервера имеет доступ к содержимому базы. HTTPS обязателен. WebRTC шифрует сам медиапоток, но не обеспечивает проверку личности собеседника независимо от сервера.

Это MVP, не готовый к публичному распространению. Нет фоновых push-уведомлений, групповых звонков, синхронизации после закрытия клиента, полноценного управления участниками, восстановления пароля, резервного копирования из интерфейса и самостоятельного удаления аккаунта. Также нужны проверка безопасности, нагрузочные тесты, настройка ограничения запросов и срока хранения данных. Не используйте для чувствительной переписки до выполнения этих работ.

## 5. Контейнер для облачного сервера

В корне есть Dockerfile. Для облачного хостинга с постоянным томом и TLS настройте `CHAT_INVITE` (длинный случайный секрет), `CHAT_DB=/data/chat.db`, `CHAT_HOST=0.0.0.0`, `CHAT_PORT=8080`. Подключите постоянный том `/data`, доступный пользователю контейнера UID 10001. Прокси платформы должен завершать HTTPS и направлять запросы на 8080. Проверка: `/health`. Не размещайте секрет приглашения в репозитории. При удалении постоянного тома теряется история. Для реального использования необходимы лимиты запросов и резервные копии. Публичное размещение не выполнено.
